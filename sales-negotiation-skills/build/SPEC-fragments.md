# 内容片段编写规范（所有内容写手必须严格遵守）

输出为**纯 HTML 片段**：不要 `<html>/<head>/<body>/<!DOCTYPE>`，不要 `<style>` 或 `<script>`。一个文件可包含多个 `<section class="page">`。使用 UTF-8 编码的简体中文。

## 1. 页面区块结构（课程模块）

每个模块一个 section：

```html

  <header class="page-head">
    <p class="kicker">模块 01 / 17 · 底层原理 · 阶段一</p>
    <h1>销售的底层逻辑与商业交易原理</h1>
    <p class="lead">两三句话：本模块解决什么问题、在知识体系中的位置。</p>
    <ul class="goals">
      <li>学完本模块，你能够……（4—6 条，动词开头）</li>
    </ul>
  </header>
  <nav class="page-toc" aria-label="本页目录">
    <ol>
      <li><a href="#m01-s1">1.1 核心问题</a></li>
    </ol>
  </nav>
  <article class="prose">
    <h2 id="m01-s1">1.1 核心问题</h2>
    <p>……</p>
    <h2 id="m01-s2">1.2 概念解释</h2>
    ...
  </article>
  <div class="mod-foot">
    <button class="btn-complete" data-mod="1">标记本模块为已学完</button>
    <div class="related"><h4>关联知识</h4><p>……<a href="#p-MOD03" data-link>模块 03</a>……</p></div>
  </div>
</section>
```

## 2. 每个模块必须包含的 12 个部分（顺序固定，h2 编号连续）

1. 核心问题 2. 概念解释 3. 底层原理 4. 理论与模型 5. 适用条件 6. 操作步骤 7. 具体案例 8. 实战工具 9. 错误与陷阱 10. 关联知识 11. 练习与测评 12. 参考来源

大型模块（03、11）可扩展为多个 h2（如 4.1、4.2），但 12 类内容不得缺失。参考来源部分用 `.ref-list`（见下）。

## 3. 允许使用的 HTML 元素与 class（CSS 契约，不得发明新 class）

- 标题：`h1`（仅 section 一个）、`h2`、`h3`、`h4`
- 段落：`p`，可用 `<strong>`、`<em>`、`<code>`
- 列表：`ul`、`ol`、`li`；步骤列表：`<ul class="steps">`，每项 `<li><b>第1步</b> …</li>`
- 提示框（证据分层，必须使用）：
  - `<div class="callout c-evidence"><p class="c-title">证据：已有研究支持</p><p>……</p></div>`（同行评审/元分析）
  - `<div class="callout c-theory"><p class="c-title">理论依据</p>…</div>`（有理论依据、效果依条件而定的方法）
  - `<div class="callout c-practice"><p class="c-title">实践建议</p>…</div>`（专家经验/企业实践，未经严格验证）
  - `<div class="callout c-example"><p class="c-title">模拟案例</p>…</div>`（虚构教学案例，必须写明"本案例为模拟案例"）
  - `<div class="callout c-warn"><p class="c-title">常见陷阱</p>…</div>`
  - `<div class="callout c-dispute"><p class="c-title">争议与不确定性</p>…</div>`
- 卡片网格：`<div class="grid-2">` 或 `<div class="grid-3">`，内部 `<div class="card"><h4>标题</h4><p>…</p></div>`
- 表格：`<div class="table-wrap"><table><thead><tr><th>…</th></tr></thead><tbody><tr><td>…</td></tr></tbody></table></div>`（必须包 table-wrap，用于移动端横滑）
- 定义条目：`<div class="def"><p class="def-term">中文名（English Term，缩写）</p><p>解释……</p></div>`
- 图示插槽：`<figure class="fig-slot" data-diagram="spin-path"><figcaption>图 3-1 SPIN 提问路径</figcaption></figure>`（data-diagram 只能取下面清单中的 key）
- 工具内嵌：在模块中引用工具库时写 `<p class="tool-ref">配套工具：<a href="#tool-T04" data-link>T04 SPIN 问题设计表</a></p>`
- 参考来源：`<div class="ref-list"><p><span class="ref-tag" data-ref="R03">R03</span> Kahneman & Tversky (1979)《前景理论》Econometrica —— 支持"损失厌恶"论断。</p></div>`
- 随堂测验：
```html
<div class="quiz" data-mod="1">
  <p class="q-title">随堂测评</p>
  <ol class="q-list">
    <li data-ans="0">
      <p class="q-stem">题干……</p>
      <ul class="q-opts"><li>选项A</li><li>选项B</li><li>选项C</li><li>选项D</li></ul>
      <div class="q-exp"><b>解析：</b>……</div>
    </li>
  </ol>
</div>
```
（data-ans 为正确选项下标，从 0 开始；每题 3—4 个选项；每模块 3—5 题）
- 实战练习：`<div class="practice"><h4>实战练习</h4><ol><li>任务描述（可实际完成，含产出物与检验标准）</li></ol></div>`
- 重点批注：`<p class="note">……</p>`（次要说明）

## 5. 引用规则（最高优先级）

1. 只能引用 `VERIFIED_SOURCES.md` 中已列出的条目，用 `[Rxx]` 标注；第二批条目 R23+ 核验完成后会追加。
2. 未列入的权威资料不要引用。确有必要时写 `<!--TODO-REF: 说明-->` 由主控统一处理，**不要自己编造**。
3. 每条参考来源格式：`<span class="ref-tag" data-ref="Rxx">Rxx</span> 作者(年份)《题名》 —— 本资料支持哪一具体结论（一句话）。`
4. 证据分层必须与来源匹配：实践框架标 `c-practice`；学术实验标 `c-evidence`；有理论但条件依赖标 `c-theory`。
5. 不得把 Cialdini、Challenger Sale、SPIN 等实践框架的结论表述为"科学已证明"。
6. 不得编造统计数字、页码、DOI、案例企业名。所有案例必须标注"模拟案例"。

## 6. 术语与语言规范

- 首次出现重要术语：**中文名（English Term，缩写）**，如 **最佳替代方案（Best Alternative to a Negotiated Agreement，BATNA）**，随后通俗解释。
- 术语在后续模块、工具、案例中必须与首次定义一致（以术语词典为准）。
- 全文简体中文；紧凑、高信息密度；禁止空话、重复定义、名词堆砌。
- 每个模块正文 2500—4500 字（模块 03、11 可到 6000 字）。
- 不得出现占位文字、TODO、"略"、"详见XX"以外的内容。
- 表格优先于长段落；一图胜千言处用 fig-slot。

高/低语境(R10)框架及局限；直接/间接表达/节奏/异议表达/冲突处理；信任建立/关系vs任务导向；时间观念/决策层级/授权/会议习惯；文化差异vs个人差异；避免按国籍刻板推断；用具体问题识别偏好；跨文化邮件/报价/会议/谈判误解；非母语英语降低歧义；书面纪要确认责任/条件/时间/数量/下一步；远程与异步沟通。地区性分析必须注明依据/范围/个体差异。

### 模块14 合同谈判、承诺管理与交易风险（阶段四）
意向/报价/订单/合同/履约关系；价格/数量/质量/交付/付款/验收/责任分配；条款与商业利益关系；范围/规格/交付标准/节点/变更控制；违约/质量索赔/责任限制/赔偿/终止/争议解决基础概念；口头承诺/书面确认/聊天记录/正式合同区别；谈判纪要与行动清单；风险识别与法务升级条件；避免过度承诺/交付不足/内部协同失败；谈判结果转化为履约条件。必须区分通用商业原则与特定辖区规则（CISG、UNIDROIT等见来源库）。
学习产出：商业条款检查表/谈判结果确认清单/法务审查风险清单。工具：T26。

### 模块15 客户关系维护与客户成功（阶段四）
信任形成机制；满意度/留存/复购/客户成功区别；期望管理/交付体验/服务响应；入驻实施成功标准；关键客户管理与分层；续约/追加/交叉/转介绍；流失风险与挽回；投诉/冲突修复/服务补救；承诺/互惠/依赖/边界；避免为关系长期牺牲利润；CLV/维护成本/服务资源配置；客户反馈改进产品流程体验。
学习产出：客户账户计划/健康度指标/复购续约跟进表/关系风险评估表。工具：T27/T28。

### 模块16 销售数据、预测与成交率优化（阶段五）

学习产出：漏斗指标字典/预测表/商机复盘模板/成交率优化框架。工具：T29/T30。

### 模块17 销售系统整合与综合实战（阶段五）
