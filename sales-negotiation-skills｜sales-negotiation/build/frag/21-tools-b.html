T19 谈判目标与保留条件表

谈判工具阶段三

适用场景：任何正式谈判前（面谈、电话、邮件议价），与 T20、T21、T23 配套使用；年度合同续约、大单议价、多轮还价前必填。核心作用：把"想谈个好价"拆成四层数字——最渴望结果（MDO，Most Desired Outcome）、目标、可接受范围、保留价（walk-away，退出价），外加每个议题的底线。没有这四层数字的谈判，现场每一个决定都是即兴发挥。配套模块 10/11。

字段与判断维度

字段判断维度与填写要点合格写法 / 反例
最渴望结果（MDO）一笔理想交易的完整画面：价格 + 全部关键条件的组合，可检验、可书面化"单价 118 万 + 预付 30% + 4 个月交期 + 12 个月质保"；反例："价格越高越好"
目标价 / 目标条件有较大把握达成、团队会认可为"谈得不错"的水平；介于 MDO 与可接受范围上沿之间"112 万，付款 30/70"；反例：把 MDO 当目标

授权边界自己能当场拍板的幅度（折扣、账期、服务范围），超权限的暂停与升级路径"5% 折扣内自主；超过须销售经理 2 小时内批复"
时间约束与期限归属双方的时间压力：谁更急？截止日期是硬约束还是谈判话术？"客户预算年度 12/31 截止（客户急）；我方 3 月起排期紧张（我急）"
依据与验证状态每个底线标注依据来源：成本核算 / 历史成交 / 估计；估计项安排验证"[成本核算]""[历史 3 单推断，待验证]"

填写方法

  1. 先算财务底线：从成本拆解出发计算保留价（成本 + 最低可接受毛利），不知道成本就没有保留价；拿不准的成本项留缓冲，不要顶到线上。
  2. 写 MDO：描述理想交易全貌，含价格与条件组合；MDO 不是"最高价"，是"最好的一整包"。
  3. 设目标：评估历史成交区间与客户支付能力，定一个有把握的目标水平。
  4. 切分可接受范围：把目标到保留价之间切成 3—4 个让步步进（供 T23 使用），逐议题列区间。
  5. 定保留价并联动 BATNA：写下"退出后我的最佳替代是什么"（转向其他客户/方案/维持现状的收益）；保留价的价值来自 BATNA，没有 BATNA 的保留价只是愿望。
  6. 标必保与可交换项：把议题分成"绝不让"与"可换"两列，防止多议题谈判中无筹码可用。
  7. 明确授权与升级：写清现场权限、暂停话术、升级路径与所需时间。
  8. 谈判前对齐：与上级/团队过一遍四层数字，避免现场被问"能再少点吗"时各自为战。

常见误用

①只写一个"保留价"不写 MDO 与目标——谈判变成"只要不低于成本就行"，本能在 102 万收手，却不知道 118 万本可拿到；②保留价顶在成本线上——不可预见的运费、返工、汇率一动就亏损，底价必须含缓冲；③所有议题都设成"必保"——没有可交换项，多议题创造价值（T22）根本无从下手；④保留价是感觉不是计算——"我觉得低于 100 万不划算"，被对方一逼就让到 95 万还自以为坚守过；⑤不写授权边界——现场打电话请示，既暴露急切又让对方看到权限漏洞；⑥时间约束只写自己的、不分析对方的——不知道谁更急，就识别不出真正的谈判杠杆。

根据结果采取下一步：四层数字已量化并获授权 → 用 T20 测算 ZOPA、T21 分析利益、T22 设计交换包、T23 排让步路径；成本依据不足 → 先做成本拆解再上桌；发现客户条件全面低于保留价（无 ZOPA）→ 按 T25 退出程序执行并转向 BATNA；谈判中对方要求超授权 → 用预设话术暂停升级，绝不当场让步。

T20 ZOPA 分析与谈判区间计算器

谈判工具阶段三

适用场景：正式报价与还价前快速测算"有没有得谈"；判断谈判任务是"争取成交"还是"争取位置"；邮件议价前的数字准备。ZOPA（Zone of Possible Agreement，可能达成协议的区域）指双方保留价之间的重叠区间：买方最高可接受价不低于卖方最低可接受价时，ZOPA 存在；反之不存在。ZOPA 概念随原则式谈判普及[R02]，本工具配交互计算器。配套模块 10/11。

字段与判断维度

字段含义与填写要点可信度分级
我的目标价T19 的目标水平，作为计算区间上端参考我方已知，高
我的保留价卖方视角 = 最低可接受价；买方视角 = 最高可接受价我方已知，高
预估对方目标价对方想达到的水平（买方想少付 / 卖方想多收）多为推断，中
预估对方保留价买方最高可付 / 卖方最低可收——ZOPA 的另一个边界多为估计，低—中，必须安排验证
ZOPA 存在性判断双方保留价有重叠 → 存在；无重叠 → 不存在（负区间）计算得出，依赖输入质量
区间宽窄与策略含义区间宽 → 锚定与让步空间大；区间窄 → 快速转向多议题交换—
对方底线的证据对方预算文件、历史成交、多方报价、客户内部人信息、口头声明逐条标注来源与日期

用下面的计算器输入四个数字（我方目标、我方保留价、预估对方目标、预估对方保留价），系统会判断 ZOPA 是否存在、算出可能成交区间与可谈空间，并给出开价锚点建议。注意：对方底线几乎总是估计值，计算器的输出是"假设检验工具"而不是"事实探测器"——把输出当作待验证假设，在谈判的信息交换阶段验证。

ZOPA 存在性判断与"无 ZOPA 时的行动"

情形判断行动
对方保留价 ≥ 我方保留价ZOPA 存在谈判任务从"能否成交"转为"在区间内拿到多好位置"：用 T22 设计交换、T23 控制让步节奏，向目标价乃至 MDO 推进
对方保留价 < 我方保留价ZOPA 不存在（负区间）不要本能性压价。依次尝试：①验证对方底线是否估计错误（问预算流程、决策标准）②改变议题结构——增减规格、服务、数量、交期，让价格与价值重新匹配（T22）③改善自己的 BATNA 或探明对方真实约束（如把"今年预算"改为"分期两年度"）④暂停等待时机变化（预算周期、项目重启）⑤接受无协议——有纪律的退出优于坏协议（T25）
单议题无区间、多议题有价值价格无 ZOPA ≠ 交易无价值把"降价"改写成"换条件"：对方要的低价可以用账期缩短、量增、范围调整来补；先拆解双方对各议题的估值差异（T22）

填写方法

  1. 取我方两数：从 T19 抄录目标价与保留价（卖方：目标高、保留低；买方相反）。
  2. 估对方两数：用对方预算信息、历史成交价、竞争对手报价、客户内部人线索推断，每条标注来源与可信度。
  3. 上计算器：输入四个数字，读取存在性判断、区间与开价建议。
  4. 做敏感性检查：把对方保留价上下浮动 5%—10% 重算——若结论对小幅估计误差敏感，说明需要先去验证而不是去谈判。
  5. 设计验证问题：为"预估对方底线"写 2—3 个可在谈判中问出的问题（预算流程、决策标准、时间压力）。
  6. 谈后回填：把实际成交价与谈判中获知的对方底线信息记入 T26 复盘，校准自己的估计能力。

常见误用

T21 利益与立场分析表

谈判工具阶段三

适用场景：谈判准备阶段；谈判陷入僵局、"对方就是不松口"时找背后原因；年度议价前理解客户的真实约束。立场（position）是对方说出来的要求，利益（interest）是要求背后的真实需求与顾虑——原则式谈判的核心原则之一是"聚焦利益而非立场"[R02]。同一个利益常有多种满足方式，这是交换设计的入口。配套模块 11。

字段与判断维度

字段判断维度与填写要点示例句式
立场陈述逐条记录对方说出的要求，用对方原话，不转述不改写"价格必须降 15%，否则今年没法谈"
推断的利益这个要求背后想满足什么：公司利益（成本、现金流、产能、风险）与个人利益（考核、位置、安全感、省事）分开列"向总经理交代降本指标；现金流紧张；测试我方诚意"
利益分类共同利益（双方都要的）/ 不同利益（目标不同但不冲突）/ 冲突利益（直接对立）共同：长期稳定供应；冲突：我方利润 vs 对方降本指标
利益强度与优先级哪些是对方"必须满足"的，哪些是"最好也有"的；强度决定交换权重"降本指标=必须（影响其年终奖）；额外培训=可选"
验证状态哪些利益已被对方亲口确认，哪些仍是我方推断；推断项配验证问题"[客户确认]""[推断-待验证]"
我方对应利益我方每个立场背后的利益同样列出——不知道自己为什么坚持，让步就没有原则"我方要 118 万：保毛利 + 不破坏明年价格基准"
交换可能我方能给的哪些东西，能满足对方利益，且我方成本低（进 T22 设计）"60 天账期可改善其现金流，我方资金成本 2.3 万"

填写方法

  1. 记录立场：把谈判前已知的对方要求逐条列出，用客户原话（来自邮件、会议纪要、历史谈判）。
  2. 追问"为什么重要"：对每条立场问"这个要求背后想解决什么问题"——准备阶段靠推断+验证问题，谈判中用信息交换阶段直接问。
  3. 区分公司利益与个人利益：采购经理的降本指标、法务的风控诉求、使用部门的省事诉求是三种不同的利益，满足方式完全不同。
  4. 分类三色：共同利益（关系基础，主动讲）、不同利益（交换空间，重点设计）、冲突利益（缩小或转化）。
  5. 检验立场与利益：问"如果利益用另一种方式满足，对方还会坚持这个立场吗？"——若答案是"会"，说明识别错了利益。
  6. 填我方一侧：同样列出我方每个立场的利益与强度，形成对照表。
  7. 标记交换入口：把"我方低成本、对方高估值"的利益对挑出来，进 T22。

常见误用

①把立场当利益——"他要降 15%"就只在价格上拉锯，完全错过"用付款条件、合同期限换降价幅度"的结构；②把猜测的利益当事实在谈判中挑明——"我知道你们现金流有问题"，猜错时信任一次性破产，利益判断必须先验证后使用；③只分析对方不分析自己——不知道自己每个立场背后的利益强度，让步时无原则、坚持时无理由；④利益分析完就完了——列了表还是各说各话，不进入交换设计等于没做；⑤把"利益"泛化成"寻找双赢"的口号——没有具体可交换项的利益清单只是姿势；⑥忽视个人利益——采购经理的 KPI 与避险诉求往往是立场的真正驱动力，只分析"公司利益"会对不上暗锁。

根据结果采取下一步：利益表完成 → 进 T22 设计多议题交换与等值报价包；关键利益仍为推断 → 列出验证问题，安排在谈判信息交换阶段问明；发现核心利益根本冲突且无交换可能 → 回 T20 重估 ZOPA、按 T25 评估退出；对方利益随谈判进程揭示新信息 → 更新本表并重算交换方案。

T24 报价策略比较表

谈判工具阶段三

适用场景：正式报价前选择"怎么开价"；应对"你们价格还有没有空间"；设计提案中的价格结构。三种基本策略：单一报价（一价到底）、锚定开价（先开出有利于我方的价格）、MESO 多套等值同时报价。选择依据：信息充分度、议题数量、市场透明度、双方关系与力量对比。配套模块 10/11。

选择决策与填写方法

  1. 数议题：只有一个变量（价格）→ 考虑单一报价或锚定开价；三个以上可变量 → 优先 MESO。
  2. 评信息：对客户预算与偏好了解少 → 用 MESO 探测（对方选哪套，就暴露了真实偏好）；信息充分 → 锚定开价直取目标。
  3. 看市场：价格高度透明可比 → 锚定幅度要小，靠结构不靠虚高；价格不透明、价值可塑 → 锚定 + 价值论证组合。
  4. 查关系：长期客户、关系敏感 → MESO（合作气候更好）；一次性交易、纯比价 → 单一报价节省成本。
  5. 验等值（MESO 专属）：三套包对我方净现值误差控制在 ±2%，逐套核算后再出门。
  6. 配依据：无论哪种策略，准备价格依据（成本/市场/价值三选一或组合，模块 10），锚点要有得说。
  7. 定预案：预写对方每种反应（接受/还价/拆包/比价）的应对，接 T23 让步表。

常见误用

①MESO 三套包不等值——对方专挑对我方最亏的那套，或识破差值后认定"这家供应商在玩心眼"，等值性是 MESO 的生死线[R23]；②锚定开价脱离依据——市场 120 万的东西开 200 万，不是锚定是吓跑，还落下不诚信的名声；③单一报价却留隐藏谈判空间——嘴上"一价到底"，客户一磨就让 3 万，价格体系与个人信用同时破产；④把单议题实验结论直接搬到复杂采购——先报价优势的实验室证据以单议题小金额为主，多议题大单中要靠交换设计而不是一个虚高锚点[R05]；⑤把 MESO 当逼单圈套用——MESO 的设计意图是展示灵活与诚意，对方感到被设计时合作气候反而恶化。

根据结果采取下一步：策略选定并完成等值核验 → 出门报价，配 T23 让步表应对还价；客户偏好不明 → 用 MESO 的选择结果反推其估值，更新 T22 矩阵；客户直接接受第一套 → 检查是否定价偏低（复盘 T26，修正 T19 目标设定）；客户 cherry picking → 重申整套等值原则，可微调但保持净值；纯比价型客户且无结构空间 → 考虑单一报价或放弃（T25）。

本部分覆盖"签约之后"与"用数据管理销售"两类场景。T27—T29 处理复杂交易条件：跨境贸易术语与成本拆解、合同条款检查、跨文化沟通适配——共同原则是把隐含义务显性化：贸易术语只划分义务边界且随版本与合同变化，合同条款背后是钱与风险，文化偏好是概率不是定论，正式场景均须核对官方文本并区分司法辖区。T30—T31 是存量客户经营：客户账户计划决定资源投向，健康度与风险预警在投诉和丢单发生前发出信号。T32—T36 把销售过程变成可测量的系统：指标字典统一口径、加权预测管理承诺、停滞与丢单诊断定位漏斗泄漏、实验记录把"我觉得"变成"数据显示"。共同纪律：口径一致先于指标好看，领先指标优先于滞后结果，每个异常都要落到下一步动作。

CIF 成本加保险费运费同 FOB：装运港装上船时风险转移卖方订舱付主运费，并自费投保（最低险别，除非合同加保）卖方办出口清关；买方办进口仅海运或内河最大误读来源：卖方买了保险 ≠ 卖方承担运输风险；险别范围要在合同写清（ICC(C) 为默许最低，可按 CIP 思路约定 ICC(A)）
CPT 运费付至货交第一承运人后风险转移卖方付至指定目的地的运费；无投保义务卖方办出口清关；买方办进口任何运输方式CFR 的陆运/空运对应版；风险在起运地已转移
CIP 运费保险费付至货交第一承运人后风险转移卖方付运费并投保；2020 版要求提升至 ICC(A) 级别（除非另有约定）卖方办出口清关；买方办进口任何运输方式与 CIF 的关键差别：CIP 保险要求更高、适用全运输方式；CIF 仅海运
DAP 目的地交货在指定目的地、卸货前的运输工具上交由买方处置；交货前风险在卖方卖方承担全程运费；无强制投保义务（实务建议）卖方办出口清关；买方办进口清关与关税任何运输方式2020 版明确卸货费用承担依合同约定——要写清"含卸货"还是"不含卸货"
DPU 卸货后交货在指定目的地卸货后交由买方处置卖方承担全程运费并卸货卖方办出口清关；买方办进口任何运输方式2020 版由 DAT 更名而来；卖方责任到卸货完成，是卖方责任最大的交货方式之一
DDP 完税后交货在指定目的地（通常卸货前，依合同）交由买方处置卖方承担全程运费卖方办进出口清关并承担进口关税任何运输方式卖方责任最大；若进口国要求进口商登记/许可（多数国家如此），卖方往往无法直接清关——此时 DDP 承诺了做不到的条件，应改用 DAP+买方进口

上表为谈判参考摘要，任何正式用途以 ICC Incoterms 2020 官方规则全文为准[R48]；术语细节随版本修订变化，合同务必注明"Incoterms 2020"及指定地点（named place）。

填写方法

  1. 先定基线口径：把报价统一拆到 FOB（或 EXW）基线，再逐项叠加到客户要求的术语——不同术语的报价不拆口径就没有可比性。

常见误用

①用 FOB 报价去和别家的 CIF 报价比价——漏算运费保险，客户拿"别家便宜"来压价，其实别家更贵，自己白让；②以为 CIF = 卖方承担运输风险——CIF 的风险转移点和 FOB 一样在装运港装上船，卖方买了保险不等于买了风险，保险赔款归索赔方；③合同里只写"FOB"不写版本和地点——术语随 Incoterms 版本演变，旧版新版本义务有差异，必须写"Incoterms 2020 + 指定港口"；④以为术语能解决一切法律问题——风险转移、所有权归属、违约救济还取决于准据法、CISG 是否排除适用、各国国内法，术语只是其中一环[R49][R51]；⑤EXW 成交却完全不装车不管出口清关——买方无出口能力时货物卡在境内，责任扯皮；⑥为了显示"服务好"承诺 DDP——进口国要求进口商登记时卖方根本无法清关，承诺了做不到的条件；⑦成本拆解漏算资金占用与汇率——账期一长、汇率一波动，账面利润全没了。

根据结果采取下一步：报价前 → 用本表拆解各术语成本并统一口径，生成 2—3 个术语选项供客户选择；与客户核对价格包含范围 → 书面确认术语 + 版本 + 指定地点 + 费用清单；客户要求不熟悉或我方难操作的术语 → 换算到可控口径再报价，或升级报关行核算；签约 → 条款细节进 T28 合同检查表；交付阶段 → 按确认的风险转移点安排保险、单证与物流跟踪。

合同工具阶段四

常见误用

冲突与异议对抗型（当面争论无妨）vs 回避冲突型（公开争执=失礼）"谈判中如果有分歧，您觉得怎么讨论最有效？"回避冲突型：不在多人场合逼问、给对方面子（私下场合处理分歧[R38]）；对抗型：直接辩论不伤关系
等级与授权平等主义 vs 层级分明"贵司这类决定通常由哪一层级最终确认？"层级文化：按对等层级对接、给足上级面子；平等文化：越级沟通成本低但也要先打招呼

跨语言与非母语沟通降歧义动作

  1. 短句与常用词：不用俚语、反讽、双关和长从句；一个句子一个意思。
  2. 数字与日期书面确认：所有关键数字、日期、数量、责任用文字 + 数字双格式写（"12 月 15 日（15/12）"），避免日/月格式歧义。
  3. 纪要闭环：每次会议后 24 小时内发书面纪要，列责任、条件、时间、数量、下一步，请对方回复确认。
  4. 复述确认：重要共识让客户用自己的话复述一遍，比"您明白了吗"可靠得多。
  5. 留出语言负担：非母语客户在复杂论证中需要更多处理时间——不把沉默当拒绝，也不把"yes"当同意（可能只是"我在听"）。

填写方法

  1. 生成假设：按上表七个维度，对具体客户生成"可能偏好"假设（可参考其文化背景，但只作假设）。
  2. 设计验证问题：每个维度配一个可直接问出的问题（上表已给模板），安排在首次会议或谈判前段自然带出。
  3. 记录实际反应：客户的实际回答与行为优先于预设——发现不符，立刻更新该客户的沟通档案。
  4. 制定适配方案：把验证过的偏好转成具体动作：邮件详略、会议议程、决策链接触顺序、确认机制。
  5. 建立客户文化档案：每个跨境客户一份，随接触更新；下次谈判前调出复用。

根据结果采取下一步：绿灯 → 按 T30 账户计划推进增购、交叉销售与转介绍；黄灯 → 客户成功/销售主导诊断与修复，设 2 周复检日；红灯 → 升级管理层介入，启动挽回与服务补救方案，暂停追加销售；若确认客户自身经营恶化（非我方原因）→ 收紧信用与交付承诺，管理退出；指标异动根因指向产品/服务 → 反馈产品与服务改进闭环，而不只做客户侧动作。

适用场景：搭建或审计销售数据体系；统一团队汇报口径；解读任何销售报表之前。每个指标给出定义、公式、计算口径、使用条件与常见误读。没有字典的销售数据，每个人都在算自己的"成交率"，会议上对不上数。数据驱动销售的前提是口径一致，其次才是仪表盘好看[R45][R46]（实践级证据）。配套模块 16。

填写方法与口径治理纪律

  1. 先写字典再看板：任何指标进报表前，定义、口径、数据源三要素先过字典评审。
  2. 时间窗一致：分子分母用同一批次（cohort 分析优先）或明确说明"期间口径"，禁止混搭。
  3. 领先指标优先：活动量、管道生成速度、阶段转化速度是领先指标；成交与收入是滞后指标——只盯着滞后指标，发现问题时已无法补救。
  4. 分组找瓶颈：任何汇总指标异常，先按来源/行业/规模/销售分组拆解，定位瓶颈环节再谈改进——盲目加量是最贵的诊断[R45]。
  5. 相关不等于因果：活动多成交多，可能是商机质量好而不是活动有效；结论前先问"有没有其他解释"。
  6. 警惕古德哈特定律：指标成为考核目标后就不再是好指标——成交率被考核，淘汰商机就会被操纵不计。

字段与填写方法

  1. 记事实：丢单后 48 小时内记录客户原话、可观察事实（谁说的、什么时候、什么场合），与解读分开写。
  2. 多因素归因：按上表七类逐一排查，每类标"主因/次因/无关"，主因不超过两个。
  3. 追问口头理由：客户说"太贵"时问"主要是总价还是付款条件？如果是总价，差距在多少以内您可以接受？"——把礼貌理由变成可分析信息。
  4. 配证据：每个主因必须附证据（客户原话/竞对信息/内部动态），无证据的归因标[推测]。
  5. 分内外因：区分"我们的动作可改进"与"市场/外因不可改"——不可改的因素记录以校正资格判断，可改的进改进清单。
  6. 季度模式识别：季度末把丢单按分类统计分布，找出重复出现的模式——一次丢单是事件，三次同类丢单是系统问题。
  7. 沉淀竞对信息：竞争类丢单同时更新竞对档案（价格带、方案特点、关系路径）。

填写方法

  1. 选问题：从丢单分析（T35）、停滞诊断（T34）、成交复盘（T26）的重复痛点中选实验题目——不测"interesting"，测"recurring"。
  2. 写假设与成功标准：先写成功标准再动手；没有成功标准的实验，事后怎么解释都行。
  3. 设计变量与分组：一次一个变量；分组要随机或分层随机，避免"方便的分配"。
  4. 定周期与样本：结果指标的周期要覆盖客户决策时长；样本量级至少能看出方向（小样本只做定性参考）。
  5. 执行并记录：原样保留两组内容（邮件原文、话术脚本）与原始结果数据。
  6. 分层解读：看总体 + 按来源/规模/客户类型分层——总体有效可能某个子群反向。
  7. 下结论与推广：写清结论、置信度、推广条件；进实验台账，防止同一实验重复做。

常见误用

①一次改多个变量——邮件改了、主题行也改了、发送时间也换了，结果涨了说不清是什么起作用，下次无法复制；②没有对照组——大促期间邮件回复涨了，不知道是改动的功劳还是季节的；③样本按"方便"分配——把熟悉的客户挑进实验组，实验开始就是结论；④周期太短——B2B 决策周期长，回复率涨了但成交率没测，可能只是吸引来更多"看看"的人；⑤只看总体平均值——总体有效、老客户子群反向，一刀切推广伤害存量关系；⑥"实验"变拍脑袋试点——没有假设和成功标准，事后怎么说都有理；⑦有效就全量推广、无效就悄悄放弃——推广条件与负结果同样要记录，负结果是团队最贵重的资产（避免别人重复交学费）；⑧样本小就下强结论——16/94 的差异值得试，但 5 vs 2 的商机差异只是噪声。

根据结果采取下一步：实验有效 → 制定推广计划（含推广条件与监控指标），推广后 30 天观察反效果；无效/不确定 → 检查样本与周期是否足够，重新设计或换假设，负结果入库；分层发现子群反向 → 只在正向子群推广；系统性实验发现 → 回对应模块更新方法与模板；建立团队实验台账，季度回顾：哪些方法已验证、哪些已证伪、哪些仍未知——把个人经验升级为团队知识。
