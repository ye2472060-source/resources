# A. 研究与定位

## 工具 1 · 用户访谈计划与问题提纲模板

**适用**：模块 1.5。**目标**：在 2 周内完成 6–10 次有效访谈，得到可验证的需求判断，而不是「用户说想要什么」。

```
【1】研究目标（本次访谈要回答的 1 个核心问题）
    Q：
    成功标准：访谈结束后，我能判断 ______（是/否）成立

【2】访谈对象
    目标人群定义：
    筛选条件（行为/角色/场景）：
    招募渠道：
    样本量：___ 人（建议每类人群 5–8 人）
    激励方式：

【3】访谈结构（60 分钟）
    0–5 min  破冰 + 说明录音用途 + 强调没有正确答案
    5–20 min 背景与现状：最近一次发生这个任务的真实过程
    20–40 min 关键事件还原（按时间线追问：当时发生了什么 → 你先做了什么 → 卡在哪 → 怎么解决的 → 花了多少成本）
    40–55 min 替代方案与支付意愿：之前试过什么？为什么换？为什么放弃？
    55–60 min 补充与推荐（"还有谁我应该聊？"）

【4】问题清单（按此顺序，避免诱导）
    开场（开放式）
    - 请讲讲你上一次 [场景] 的完整经历，从开始到结束。
    - 当时是什么让你决定要解决这个问题？
    过程（追细节，不问"你会不会用"）
    - 那一步你具体做了什么？能演示给我看吗？
    - 中途有没有卡住？卡在哪？后来怎么办？
    - 这件事你多久做一次？上一次是什么时候？
    替代与切换
    - 在这之前你用什么办法？为什么换掉了？
    - 是什么让你终于下决心换的？
    - 有没有试过又退回原来办法的时候？为什么？
    成本与意愿
    - 这件事如果没解决，对你造成什么实际影响？
    - 你为解决这个问题花过钱/花过多少时间吗？
    收尾
    - 如果只能改一件事，你希望改什么？
    - 还有谁我应该聊？

【5】禁止事项（勾掉易犯的）
    □ 不问"你是否喜欢这个功能"（未来假设，不可信）
    □ 不描述自己的方案后再问评价
    □ 不问"你会付多少钱"（改问过去实际支付行为）
    □ 不一次问多个问题
    □ 不反驳用户，不解释产品

【6】记录格式（每次访谈一页）
    用户代号 / 角色 / 场景：
    触发事件（Push）：
    期望结果（Pull）：
    原有方案与不满（现状）：
    焦虑与顾虑（Anxiety）：
    习惯与惯性（Habit）：
    原话引用（≥3 条）：
    本研究假设是否被支持： 支持 / 反驳 / 不确定（依据：______）
```

**常见错误**：把访谈当成需求征集会；样本全是「友善的熟人」；只记录结论不记录原话；一次访谈后就下判断。

| 痛点 | 发生频率 | 严重程度(1-5) | 现有应对 | 证据来源 |
|---|---|---|---|---|

决策与阻力
- 决策者 / 使用者 / 付费者是否同一人：
- 采购/尝试的主要顾虑：
- 信息与信任来源：

- 常出现的信息渠道：
- 关键影响人/社群：

- 我们提供的核心价值：

## 工具 3 · 用户需求分析优先级评估表

**适用**：模块 1.9、2.7。

```
优先级评分（每项 1–5）
| 需求（用户任务表述） | 影响人数 | 发生频率 | 痛苦程度 | 现有方案糟糕程度 | 与我们战略匹配度 | 实现成本(反向:越高分越低) | 总分 | 证据支撑 |
|---|---|---|---|---|---|---|---|---|

权重建议：影响人数×2、痛苦程度×2、战略匹配×2、频率×1、现有方案×1、成本×(−1)
排序后检查：
□ 前 3 名需求是否来自同一类用户？（是 → 细分可能有问题）
□ 评分最高的需求，有没有真实行为证据（不只是访谈说法）？
□ 有没有"用户都说要、但没人真做"的需求在前排？（警惕伪需求）
□ 三角验证：定性（访谈）+ 定量（行为数据/问卷）+ 观察，三类中至少两类支持？
```

## 工具 4 · 产品定位与价值主张模板

**适用**：模块 2.1–2.6。

```
【价值主张画布】
用户任务（Job）：
痛点（Pains）：         收益（Gains）：
    1.                     1.
    2.                     2.
    3.                     3.
我们的产品/服务：
  止痛（Pain relievers）：   增益（Gain creators）：
    1.                         1.
    2.                         2.
匹配度检查：痛点 ___/3 被止痛；收益 ___/3 被创造。不匹配项需调整定位或产品。

【定位语句】（Moore 式模板）
对于 [目标用户]
他们 [关键需求/任务，与竞品不同的痛点]
我们的产品是 [品类]
它能 [核心价值/关键收益]
不同于 [主要替代方案]
我们 [差异化的关键能力/理由]

【有效定位的四条检验】
□ 是否明确排除了部分用户？（不敢排除 = 没有定位）
□ 用户能否用自己的话复述出差异？
□ 差异点是否可被验证（有证据），而非形容词（"更好用""更智能"）？
□ 是否同时说明了"为什么是我们"（能力/资源/机制支撑）？

【PMF 信号检查】
□ Sean Ellis 测试："如果不能再使用本产品，你的感受？" → 非常失望占比 ___%（经验参考阈值 40%）
□ 同期群留存曲线是否走平（不再持续下滑）？
□ 是否有自然增长（口碑/自发推荐占比）？
□ 付费用户留存是否接近免费用户留存？
注意：40% 为经验阈值，不是定律；且受样本构成影响。
```

## 工具 6 · 产品需求与 MVP 验证清单

**适用**：模块 2.8。

```
【假设清单】
| 假设 | 类型（价值/增长/可行性） | 若不成立的影响 | 验证方式 | 成本 | 优先级 |
|---|---|---|---|---|---|

【MVP 定义】
我们要验证的核心假设（只选 1 个）：
MVP 包含（最小集合）：
明确不包含（写下来，防止范围蔓延）：
成功标准（可量化、提前约定）：______ → 达标 / 不达标
失败标准（提前约定，避免事后找理由）：

【验证方式选择】（按成本从低到高）
□ 现有数据/日志分析      □ 用户访谈（5–8 人）
□ 落地页/假门测试        □ 人工模拟（Wizard of Oz）
□ 单功能原型             □ 小流量 A/B
□ 完整功能上线
原则：能用更便宜的方式验证，就不要先做功能。

【最小可行实验 vs MVP 的区别】
MVP = 做出一个最小产品；最小可行实验 = 用最低成本获得判断。
很多时候落地页 + 支付意愿测试，比做 MVP 更快回答"有没有人想要"。

【复盘检查】
□ 成功标准是事前定的吗？（事后定标准 = 自欺）
□ 有没有因为"沉没成本"而继续？
□ 结果不达标时，是"假设错"还是"实现/渠道错"？能区分吗？
```

## 工具 8 · AARRR 漏斗分析表（可计算）

**适用**：模块 3.2、3.3。（网站内为可输入的实时计算器）

```
输入：
获客（Acquisition）    ______ 人
激活率（Activation）   ______ %
次留/留存率（Retention）______ %
变现率（Revenue）      ______ %   客单价/ARPU ______
推荐率（Referral）     ______ %   人均邀请带来新用户 ______

计算（自动）：
激活用户 = 获客 × 激活率
留存用户 = 激活 × 留存率
付费用户 = 留存 × 变现率
收入     = 付费用户 × ARPU
推荐新增 = 付费用户 × 推荐率 × 人均带来
循环后总获客（K = 推荐新增 / 初始获客；K<1 时收敛）= 初始获客 / (1 − K)

输出检查：
□ 哪一环节转化率最低？（瓶颈通常在最弱环节，而非投入最多环节）
□ 提升 1 个百分点的收益，哪个环节最大？（算一遍再决定资源）
□ K 因子是否 ≥ 1？如果远小于 1，不要指望病毒增长
□ 留存是否为最弱环节？是 → 先修留存再投获客（否则漏水桶）
```

## 工具 9 · 增长实验假设设计模板

**适用**：模块 4.1、4.2。

```

【优先级评分】

□ 是否重复验证了已知结论？（避免做"一定会赢"的假实验）
```

| 指标 | 对照 | 实验 | 相对变化 | p 值 | 置信区间 | 显著? |
主指标：
护栏指标 1：
护栏指标 2：
诊断指标：

【结论】
□ 显著正向 → 上线，并监测长期影响（留存/收入是否同步改善）
□ 显著负向 → 不上线，记录原因
□ 不显著 → 记录"样本是否足够 / 效应是否真的存在"，决定扩样或放弃
失败类型归类：□ 假设错 □ 实现错 □ 度量错 □ 流量/样本不足 □ 效应太小无价值

【必须记录的三件事】
1. 我们原本相信什么（假设）  2. 实际发生了什么  3. 我们因此改变了什么认知

## 工具 15 · 增长项目优先级评估（RICE，可计算）

**适用**：模块 2.7、4.2、9.3。

```
| # | 项目/假设 | Reach（每季度影响人数） | Impact（3 巨大/2 高/1 中/0.5 低/0.25 微小） | Confidence（100%/80%/50%，低于 50% 先做研究） | Effort（人月） | RICE 分 |
|---|---|---|---|---|---|---|
| 1 |  |  |  |  |  |  |
| 2 |  |  |  |  |  |  |
| 3 |  |  |  |  |  |  |

RICE = (Reach × Impact × Confidence) ÷ Effort

使用纪律（常见误用）：
□ Reach 用同一时间窗口、同一口径的人数，不要混用
□ Impact 只用固定 5 档，不要自定义小数（虚假精确）
□ Confidence 低于 50% 说明信息不足 → 先做研究，而不是硬排
□ Effort 要包含设计+开发+测试+上线全周期，不只是开发
□ 由多人独立打分后讨论分歧，不要单人拍板
□ RICE 是排序工具，不是投资回报计算；大额投入仍需单独算单位经济
```

## 工具 14 · 单位经济模型计算器（可计算）

**适用**：模块 6.6、6.7。（网站内为实时计算器）

```
输入：
ARPU（每用户月均收入）= ______
毛利率 = ______ %
月流失率 = ______ %
CAC（单用户获客成本）= ______

计算：
每用户月贡献利润 = ARPU × 毛利率 = ______
平均生命周期（月）= 1 ÷ 月流失率 = ______
LTV（简化、未折现）= 月贡献利润 × 生命周期 = ______
LTV / CAC = ______
CAC 回本周期（月）= CAC ÷ 月贡献利润 = ______

判读（经验参考，非定律）：
□ LTV/CAC ≥ 3（经验线，需结合行业与回本周期）
□ 回本周期：B2C 通常希望 ≤ 6–12 个月；B2B 可更长但要看现金流
□ 若 LTV/CAC 低：优先降 CAC 或提留存，而不是先涨价

B2B 补充指标：
GRR（总收入留存）=（期初收入 − 流失 − 降级）÷ 期初收入
NDR（净收入留存）=（期初收入 − 流失 − 降级 + 扩张）÷ 期初收入
□ NDR > 100% 说明存量扩张能抵消流失，是高质量增长信号
□ Rule of 40（增长率% + 利润率% ≥ 40）为 SaaS 经验启发式，不是定律

重要提醒：这是**未折现的简化模型**。正式决策应使用折现现金流、分群 LTV、
并区分自然流失与非自然流失；获客成本也要用分渠道口径，避免"混合 CAC"掩盖亏损渠道。
```

## 工具 17 · 产品运营常用指标与计算公式速查表

| 类别 | 指标 | 公式 / 定义 | 常见陷阱 |
|---|---|---|---|
| 获客 | CAC | 期间获客总投入 ÷ 期间新增用户数 | 用混合 CAC 会掩盖亏损渠道；要分渠道算 |
| 获客 | 混合 CAC 陷阱 | 总投放 ÷ 总新增 | 自然流量拉低平均值，误以为投放划算 |
| 激活 | 激活率 | 完成关键行为的用户 ÷ 注册用户 | "关键行为"必须来自留存关联分析，不能拍脑袋 |
| 激活 | 注册 vs 激活 vs 首次关键行为 | 三个不同概念，口径必须分开 | 用注册数当激活数会高估 |
| 留存 | 次日/7日/30日留存 | 第 N 日仍活跃的用户 ÷ 第 0 日新增用户 | 必须用**同期群**口径，不可用大盘活跃/总用户 |
| 留存 | 流失率 | 1 − 留存率（口径需与留存定义一致） | 不同团队定义不同，跨团队比较前先对齐 |
| 留存 | 活跃定义 | DAU/WAU/MAU；"活跃"需明确为哪类行为 | 把"打开"当活跃会虚高；把"核心操作"当活跃更严格 |
| 留存(B2B) | GRR / NDR | 见工具 14 | NDR 含扩张，不能替代 GRR 看健康度 |
| 变现 | ARPU | 期间收入 ÷ 活跃用户数 | 分母口径（DAU/MAU/付费用户）不同，数值差异大 |
| 变现 | ARPPU | 期间收入 ÷ **付费**用户数 | 与 ARPU 混用会误导 |
| 变现(B2B) | MRR / ARR | 月度/年度经常性收入 | 一次性收入、服务收入不应计入 |
| 单位经济 | LTV（简化） | ARPU × 毛利率 ÷ 月流失率（**未折现**） | 未折现会高估；流失率取错会大幅偏差 |
| 单位经济 | LTV / CAC | 见工具 14 | 3 是经验值不是定律 |
| 单位经济 | CAC 回本周期 | CAC ÷（ARPU × 毛利率） | 只看 LTV/CAC 不看回本，可能现金流断裂 |
| 增长 | K 因子 | 每个用户带来的新用户数 | K<1 时病毒增长会衰减，不可依赖 |
| 增长 | 病毒周期时间 | 从使用到完成邀请邀请的平均时长 | 周期长的病毒增长即使 K>1 也慢 |
| 实验 | 样本量（比例） | n =（z₁₋α/2 + z₁₋β）² × [p₁(1−p₁)+p₂(1−p₂)] ÷ (p₁−p₂)² | MDE 越小，样本量按平方增长 |
| 实验 | 样本量（均值，经验） | n ≈ 16σ² ÷ δ²（每组） | 来自 Evan Miller，为经验近似 |
| 实验 | 相对提升 | (实验组 − 对照组) ÷ 对照组 | 用绝对差还是相对提升要提前说清 |
| 优先级 | RICE | Reach × Impact × Confidence ÷ Effort | Impact/Confidence 用固定档位，避免虚假精确 |
| 优先级 | ICE | Impact × Confidence ÷ Ease | 比 RICE 粗，适合早期快速排序 |
| 渠道 | 渠道 ROI | 渠道带来的 LTV ÷ 渠道 CAC | 用首单收入算 ROI 会低估长期价值 |
| 数据 | 辛普森悖论 | 分组结论与整体结论相反 | 拆解时必须下钻到同质子集 |
| 数据 | 古德哈特定律 | 指标成为目标后不再是好指标 | 必须配护栏指标 |

## 附：使用这些模板的三条原则

1. **事前写、事后不改**：成功标准、假设、样本量必须在执行**之前**写下来。事后补写的假设没有价值。
2. **先便宜后昂贵**：能用现有数据/访谈/落地页回答的问题，不要先做功能或先投广告。
3. **每次都留下一句话沉淀**：写成「在 X 情境下，对 Y 人群做 Z，通常会得到 W」的句式，长期积累成你自己的增长知识库（模块 9.5、9.6）。
