## 2. 如何打开

**方式一（推荐，零依赖）**
双击 `product-operations-growth-academy.html` → 在任意现代浏览器（Chrome / Edge / Firefox / Safari 最新版）中打开即可。

**方式二（本地起服务，可选）**
```bash
# 在文件所在目录执行（任选其一）
python -m http.server 8080
# 然后浏览器访问 http://localhost:8080/product-operations-growth-academy.html
```
两种方式功能完全一致；离线（断网）亦可正常使用，因为所有 CSS/JS/SVG 均内联在单文件中。外链仅出现在「可点击跳转的原始资料链接」上，需要联网才会打开。

**建议**：使用电脑端宽度 ≥ 1280px 浏览体验最佳；手机/平板会自动切换为单列 + 抽屉式导航。

## 5. 证据分级约定（重要）

课程中所有内容都标注了四类证据，请务必区分：

| 标签 | 含义 |
|---|---|
| **已验证事实** | 有第一手/权威来源可核验的事实（如 Google Optimize 于 2023-09-30 停止、Evan Miller 文中给出的 26% 假阳性数据） |
| **广泛使用的框架** | 业界通用方法论，有公认出处，但本身是「思考工具」而非自然定律（如 AARRR、RICE、HEART、JTBD） |
| **推理判断** | 基于公开信息与逻辑推导得出的判断，可能随情境变化，需自行验证 |
| **教学模拟数据** | 为教学演示**虚构**的数字，**不是任何真实公司的数据**（模块 4 的三个 A/B 案例、模块 5 的同期群表、模块 7 的教学案例、模块 10 的三个综合项目均为此类） |

凡是「经验阈值」（如 LTV/CAC ≥ 3、PMF 40%、Rule of 40）在课程中都明确标注为**经验启发值而非定律**，并给出失效条件。案例中的二手数字（如 Dropbox 推荐带来的增长比例）标注为「公开报道，未经原公司确认」。

| 数据一致性 | 自建 `check_sources.py` / `check_docs.py` / `check_cats.py`：逐字段比对文档与页面内嵌数据 | **PASS**：37 条来源的 URL 与描述 100 一致（0 缺失/0 多出）；术语表 84 条的 8 个分类与筛选按钮完全匹配；术语与来源引用的 11 个模块无悬空；99 个单元标题与文档清单逐条一致 |
| 离线可用性 | 单文件、无外部 CSS/JS/字体/图片依赖（字体走系统字体栈） | 通过 |

**未做/无法完全保证的部分（如实说明）**：
- jsdom 不实现真实布局与滚动，因此「视觉呈现、真实滚动行为、打印分页效果」未经像素级验证；响应式是按断点与 `max-width`/`overflow` 规则设计的，建议在真实浏览器窗口缩放确认一次。
- 部分经典著作（如 Christensen《Competing Against Luck》、Eyal《Hooked》）为**第一层原始著作但未在线核验全文**，已在资料库中标注。
- 公开案例的二手数字无法回溯到公司原始披露，已按「公开报道」标注。
- 计算器使用**简化模型**（如 LTV 未折现、VWP 假设对数正态），页面内已写明假设与边界，不能替代正式财务/定价研究。

源文件在 `_build/` 下按「内容分片」组织，便于局部修改：

```

_build/part04-m1.html … part13-m10.html   # 模块 1–10
_build/part14-toolbox.html         # 工具箱（18 个工具：11 模板 + 6 计算器 + 1 速查表）

_build/part16-glossary-sources.html# 术语表 + 资料库 + 目录/回到顶部/搜索弹窗
```

**改完如何重新生成主文件**（在 `_build/` 目录下执行）：

```bash

    part06-m3.html part07-m4.html part08-m5.html part09-m6.html part10-m7.html \

    part15-cases-assess.html part16-glossary-sources.html part17-js.html \

```

**回归验证**：

```bash
python validate.py                 # 结构校验，期望 PASS
python check_docs.py               # 文档声明与 HTML 实际内容一致性核对
node --check _build/extracted.js   # JS 语法（需先从 HTML 提取 <script> 内容）
node runtime-test.js               # 运行时交互，期望 31/31（需 NODE_PATH 指向含 jsdom 的 node_modules）
```

常见修改点：
- 新增/修改术语、来源、模块元信息 → 改 `part17-js.html` 顶部的 `GLOSSARY` / `SOURCES_CORE` / `SOURCES_TOOLS` / `MODULES` 数组。
- 新增知识单元 → 在对应模块分片里加 `<div class="unit" id="uX-Y">` 区块；搜索与目录会自动纳入（搜索索引由 DOM 实时构建）。
- 修改配色/字号/间距 → 改 `part01-head.html` 中 `:root` 与 `[data-theme="dark"]` 的 CSS 变量。

## 8. 快速上手建议

1. 打开首页，先看「四阶段学习路径」与「模块总览」，再点「知识地图」看依赖关系，建立整体结构感。
2. 从模块 0 开始顺序学。每读完一个知识单元，**做完「练习任务」再勾「已完成」**，不要只看不练。
3. 学到模块 3/4 时，打开工具箱里的**指标树、A/B 样本量、AARRR** 三个工具，用你自己的产品数据跑一遍。
4. 学完模块 5/6 后，用**单位经济计算器**和 **Van Westendorp 计算器**做一次测算。
5. 最后进模块 10 的三个综合项目（B2B SaaS 0→1、B2C 订阅制、社区平台商业化），**先自己写方案，再展开参考答案对照**。
6. 全部学完后做「能力自评」，把薄弱维度对应的模块重学一遍。
