模板库：可复用的写作组件

一句话定位：把课程中重复出现的写作任务固化为模板——点击「复制」即可取用，使用前先读使用条件。

所有模板中的方括号 [ ] 为待填项。模板是起点不是枷锁：场景不匹配时，按模块 03的原则重组结构。

1. 写作任务简报

任务简报 · 任何正式写作动笔前填写
【文档名称】
【文档类型】报告 / 备忘录 / 邮件 / 操作指南 / 提案 / 演示
【读者】主要读者：；次要读者：；决策者：
【读者现状】对该话题已知：；立场（支持/中立/反对）：；核心顾虑：
【写作目的】读者读完后应：知道 ___ / 相信 ___ / 决定 ___ / 执行 ___
【核心信息】一句话：
【成功标准】怎样算写成了：
【约束】篇幅：；截止时间：；媒介：；必须包含/不得包含：
【风险】如果写失败，最可能的原因是：

使用条件：任何超过 20 分钟的写作任务都值得填写。读者立场为「反对」时，必须走模块 10的异议处理流程。

2. 读者分析卡

读者分析 · 决定结构、语言与证据选择
读者画像
- 角色与决策权：
- 已有知识（避免过度解释）：
- 知识缺口（必须补的解释）：
- 最关心的问题（前三位）：
- 最大顾虑/反对理由：
- 行动成本（读这份文档要他付出什么）：
- 阅读场景（整块时间/碎片时间；屏幕/纸质；独自读/会上读）：
- 阅读方式（从头读/跳读/只读摘要）：

对结构的含义：
- 结论前置程度：
- 需要多少背景：
- 证据类型偏好（数据/案例/权威）：
- 语言正式程度：

3. 金字塔大纲

金字塔大纲 · 报告/方案/邮件通用
S（情境）：读者已知且认同的背景
C（冲突）：打破稳定的问题/变化/机会
Q（问题）：由冲突引出的待决问题
A（答案）：核心结论（结论先行）

支撑层（回答 Q 的理由，MECE 分组）：
1. 理由一：___（归纳：同类事实并列）
   1.1 事实/数据：___
   1.2 事实/数据：___
2. 理由二：___
3. 理由三：___

纵向检验：每个理由是否直接支撑 A？同组理由是否互斥且穷尽？
读者检验：反对者会先攻击哪一条？

4. Toulmin 论证图谱表

论证图谱 · 建立可审查的论证链
主张（Claim）：
依据（Grounds）：
推理规则（Warrant）：由依据推出主张的许可是：
支撑（Backing）：推理规则的可信度来自：
限定（Qualifier）：主张在 ___ 条件下成立，强度为：通常/很可能/在一定范围内
反驳（Rebuttal）：主张在以下情况不成立：；已有反例：
对反驳的回应：/ 承认并修正主张为：
替代解释：；为何我的解释更优：

5. 决策备忘录

决策备忘录 · 推动管理层决策
【标题】结论式标题：建议 ___，以解决 ___

一、结论与建议（3 行以内）
二、需要做出的决策
- 决策点：；选项 A/B；建议选项；理由（1 句）
- 所需批准：；截止时间：
三、现状与问题（事实与数据分区）
四、原因分析（机制，而非罗列现象）
五、选项比较（成本/收益/风险/周期）
六、风险与应对
七、下一步（负责人 + 期限）
附：证据来源清单

6. 商业邮件模板库

6.1 请求协助

邮件 · 请求协助 · 需明确对方成本与拒绝空间
主题：[请求] 需要你在 [日期] 前提供 [具体材料] 用于 [用途]

[称呼]，

为完成 [任务/项目]，需要你协助提供 [具体内容]。预计占用你约 [时间]。

具体要求：
1. [材料/动作一]，用途是 [为什么需要]
2. [材料/动作二]

如 [日期] 前提供，我们能 [具体收益]。如时间紧张，可先给 [最低可行版本]，其余 [截止日] 前补齐。

有任何问题随时沟通。谢谢！

[署名]

6.2 汇报进展

邮件 · 汇报进展 · 结论先行 + 风险明示
主题：[项目] 进展汇报：[截至 X 月 X 日] 状态 [正常/有风险/已延期]

[称呼]，

[项目] 当前状态：[一句话结论]。

已完成：
1. [事项]，结果 [可验证的结果]
2. [事项]

进行中：[事项]，预计 [日期] 完成。

风险与需要的支持：[如有，写清影响与选项；如无，写「目前无阻塞项」]

下次汇报：[日期]。

[署名]

6.3 礼貌拒绝

邮件 · 拒绝 · 先谢 + 明因 + 给替代
主题：Re: [原主题]

[称呼]，

谢谢你的邀请/提议。

这次无法参与，原因是 [具体、真实的原因，不堆砌借口]。

[可选：以后有机会很乐意 ___。]

[替代方案：] 建议你考虑 [具体替代路径/人选]，如需要我可以 [帮什么]。

祝 [项目/活动] 顺利。

[署名]

6.4 催办

邮件 · 催办 · 升级前最后确认，默认对方只是忙
主题：Re: [原主题] — 确认 [事项] 的时间节点

[称呼]，

跟进一下 [日期] 邮件中提到的 [事项]。[截止日期] 临近，想确认进度是否符合预期。

如果已在进行中，无需回复具体内容，告诉我预计完成时间即可。
如果遇到困难或需要调整优先级，我们可以现在对齐。

[署名]

6.5 表达不同意见

邮件 · 不同意见 · 先共识后分歧，对事不对人
主题：关于 [议题] 的一点不同看法

[称呼]，

感谢 [方案/邮件]。我同意 [共识部分]，这部分没有问题。

关于 [分歧点]，我的看法是 [你的判断]，依据是 [事实/数据/推理]。

我可能漏掉了 [对方掌握而我不知道的信息]。如果你能从 [角度] 补充，我很乐意修正结论。

如果方便，建议 [会议/短讨论] 对齐 15 分钟。

[署名]

6.6 澄清误解

邮件 · 澄清 · 只澄清事实，不指责
主题：澄清：关于 [事项] 的实际情况

[称呼]，

注意到 [对方来信/会议上] 提到 [被误解的内容]。为避免后续决策基于错误信息，澄清如下：

实际情况是：[事实 + 来源]。
可能的误解来源：[差异在哪里，如口径不同/信息版本不同/转述遗漏]。

不是要区分责任，只是希望 [决策/协作] 基于同一组事实。如我的理解有误，请指出。

[署名]

9. 分层编辑清单

编辑清单 · 按顺序执行，不要跳层
第一轮 结构修订
- [ ] 结论是否前置且一句话可概括
- [ ] 章节顺序是否符合读者任务
- [ ] 是否有重复、遗漏、错位内容
- [ ] 每段是否能说出功能（观点/证据/过渡/背景）

第二轮 论证审查
- [ ] 每个主张是否有依据
- [ ] 依据与主张之间推理规则是否写明
- [ ] 反方与替代解释是否处理
- [ ] 结论是否超出证据范围；限定是否保留

第三轮 事实核查
- [ ] 数字、日期、专有名词与来源核对
- [ ] 引用是否为原始来源，转述是否准确
- [ ] 相关是否被写成因果

第四轮 句子编辑
- [ ] 长句拆分；修饰关系无歧义
- [ ] 名词化改写为动词表达（除必要概括）
- [ ] 删除套话与空洞形容词
- [ ] 术语前后一致

第五轮 校对
- [ ] 标点、格式、编号连续
- [ ] 图表编号与正文引用对应
- [ ] 错字与语法

10. AI 写作提示词模板

10.1 任务拆解式起草

提示词 · 起草单个章节（人工核查前）
背景：[项目/文档背景，2-3 句]
任务：起草「[章节名]」一节
读者：[角色、知识水平、立场]
目标：读者读完后应 [知道/相信/决定/执行] ___
必须包含的信息：[要点列表]
限制：[篇幅、语气、不得包含的内容]
已知事实与数据（仅限这些，不得补充）：[列表]
输出格式：[结构要求]

注意：只使用我提供的事实；如信息不足，用 [待补充] 标注，不要编造。

10.2 反方审查

提示词 · 让 AI 扮演反方
以下是[我的提案/论证文本]。
请扮演最挑剔的[决策者/反对者]，只做三件事：
1. 指出 3 个最可能被攻击的逻辑弱点（引用原文位置）
2. 指出证据不足以支持结论的地方
3. 提出 2 个我未考虑的替代解释
不要修改文字，不要鼓励我。按攻击力排序。

10.3 受众适配

提示词 · 同内容改写为不同受众
以下是[原文]。
请改写为面向[新受众]的版本，保持事实与结论不变。
新受众特征：[知识水平、关注点、顾虑]
改写要求：调整 [背景量/术语密度/证据类型/行动要求]，不得改变任何事实、数字与结论强度。
输出后列出：你为适配受众做出的 5 个关键调整及理由。
