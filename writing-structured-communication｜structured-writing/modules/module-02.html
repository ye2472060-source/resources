模块 02 · 逻辑思维与结构化思考

一句话定位：动笔之前把问题想清楚——本模块提供推理识别、概念分析、因果辨析、五层信息区分与问题拆解工具，并产出一份可复用的逻辑检查表。

A. 学习导航

本模块解决什么问题

很多人写作卡壳不是文字能力问题，而是思考没完成：论据和结论隔着一条没说明的河；「我认为」被写成事实；同时发生的两件事被说成因果；概念前后偷换却无人察觉。本模块把这些漏洞变成可逐条检查的对象：先识别推理类型，再用五层区分检验每句话的身份，然后用树状工具拆解复杂问题，最后用检查表扫出逻辑链条里的跳跃、矛盾与隐含前提。学完后，面对任何复杂材料都能先完成一次「逻辑体检」。

学习目标

  • 能区分演绎、归纳、溯因三种推理，并判断结论强度是否被夸大
  • 能写出可操作的概念定义，识别概念边界争议，用单一标准做不重叠、不遗漏的分类
  • 能区分相关关系与因果关系，判断一段解释是否给出了机制
  • 能识别论证中的前提、假设、约束条件与结论，并标出隐含前提
  • 能将混杂材料拆成事实、解释、推断、评价、建议五层，并指出层间混淆
  • 能用问题树/逻辑树拆解复杂问题，指出链条中的跳跃、矛盾与常见谬误并输出检查报告

前置知识

模块 00（六维度评价表中的「逻辑质量」维度）、模块 01（问题陈述与问题拆解）；本模块把「问题拆解」展开为完整工具集。

B. 系统化知识讲解

B.1 三种推理：演绎、归纳与溯因

日常与工作中的推理几乎都可归入三种，混淆它们是结论说过了头的头号原因。

演绎推理（deduction）从一般前推到特定，经典形式是三段论：大前提（所有 M 都是 P）→ 小前提（S 是 M）→ 结论（S 是 P）。它保真而不增益：前提真且形式有效，结论必然真，但信息量不超出前提。失效方式有二：形式无效（中项不周延：「猫是哺乳动物，狗是哺乳动物，所以猫是狗」）；前提存疑（大前提是错的，演绎照样推出错结论，且形式漂亮）。

归纳推理（induction）从多个观察得出一般结论，增益而不保真：结论超出已观察范围，故只有概率强度，可靠性取决于样本代表性与数量。典型失效是仓促概化：「三个大区试点复购提升，故方案能提升复购」——三个大区代表全国吗？

溯因推理（abduction）为令人惊讶的观察寻找最可信解释：观察到 P；若假设 H 为真则 P 可被解释；没有竞争假说能同样好地解释 P；故暂时接受 H。Booth、Colomb 与 Williams（《研究是一门艺术》The Craft of Research, 4th ed., 2016）称之为最佳解释推论，是诊断与归因的主推理形式，产出的是假设而非结论——「能解释」不等于「已证明」；软肋是确认偏误，防御是显式列出竞争性假说并各设证伪条件。

三者结论强度依次为必然、概率、或然的假设；且都可能「形式没问题但内容塌方」——演绎的前提、归纳的样本、溯因的假说集必须单独审查，这是模块 04 把证据与推理规则分开评估的原因。

B.2 概念：定义、边界与分类

概念是思维的单元，命题真假与论证有效性都建立在概念清晰之上。定义要回答：指什么对象、依据什么特征判定。写作中常用三种：词典定义（约定用法，对专业概念往往过宽）；操作定义（用可观察、可测量的操作界定，如「活跃用户 = 7 日内完成一次核心行为的用户」——直接规定口径，是消除争议最有效的工具）；规定定义（为本文目的临时约定，必须显式声明，否则读者会用默认理解替换）。

概念边界是概念的适用范围，边界处有灰色情形。边界争议不可怕，可怕的是不声明边界却把结论推到边界外；规范动作是给出判定标准。

分类按选定标准把对象分组，质量标准是 MECE（mutually exclusive, collectively exhaustive，互斥且穷尽）。MECE 是拆解工具，不是对现实世界的形而上学断言——它要求的是「在你选定的单一维度下」不重叠。三个实操要点：① 一次只用一种标准——「按规模分」与「按行业分」混在一层，就会出现「金融大客户」归哪组的重叠；② 粒度服务于决策，由「读者要做什么决策」反推；③ 拿具体对象逐一试归类：归不进任何组是遗漏，归进两组是重叠。

用法：动笔前列出核心概念各写一行操作定义，完稿后反向检查全文判定是否一致。概念偷换不破坏任何单句，只破坏句间关系，是最隐蔽的逻辑错误。

B.3 因果关系、相关关系与机制解释

相关关系（correlation）是两个变量共变：A 上升时 B 也上升。因果关系（causation）是一个变量导致另一个变化。从相关到因果隔着三道关卡：方向（是 A 导致 B 还是 B 导致 A？）；混淆变量（是否存在 C 同时导致两者？如冰淇淋销量与溺水相关，共同原因是气温）；机制（A 通过什么过程导致 B？）。

机制解释（mechanistic explanation）把「A 导致 B」展开为「A 改变 → 中间环节 1 → B 出现」，每个环节可观察或可验证，是区分真因果与伪因果的核心证据。注意：时间先后不等于机制——「改革后利润上升」只说明先后，同期市场、汇率、对手失误都可能是真因。

写作规范：说「导致」时，要么给出机制链条，要么把动词降级为「与……相关」；反向也要警惕——否定因果不等于肯定无关，拿不出机制只是「因果未证实」，不是「因果被证伪」。

B.4 假设、前提、约束条件与结论

一段推理由四种成分构成：

  • 前提（premise）：推理明确或隐含依据的命题；省略前提靠读者脑补，错了论证就塌了。
  • 假设（assumption）：未经检验但被暂时接受为真的命题。区别在出场方式：前提是拿来用的，假设是拿来赌的。例：「假设下季度单量持平，按当前价差年省 X 万元。」假设必须显式列出。
  • 约束条件（constraint）：必须满足的限制（预算、时间、合规、人力）。它不是推理链的一环而是推理的边界——结论只在约束内成立。
  • 结论（conclusion）：要求被接受的命题。识别方法：删除某句后若其余部分变成「为某句话服务的材料」，那句就是结论——别轻信「所以」「因此」，它们常只是语气词。

结论超出证据支持范围是本模块最重要的纪律：证据支持的范围由证据的类型、数量与口径决定。降级结论的标准操作：「方案能提升复购」→「在三个试点区域观察到复购提升，扩大前需验证区域差异」——强度与证据匹配，文档反而更可信。

B.5 抽象与具体、整体与部分

抽象阶梯：同一对象可站在不同高度描述：「降低 3 号线换模时间」具体，「提升设备综合效率」抽象，「打造世界级制造体系」更抽象。抽象的价值是覆盖更多情形；风险是脱离可检验的具体命题——「提升效率」无法证伪因此也无法行动。经验规则：抽象给方向，具体给验证。

整体与部分：复杂系统可分解，但整体不等于部分的简单加总——部分互动会产生单独看部分看不到的性质（涌现）。两个写作纪律：① 子问题各自为真，未必推出整体为真（每个部门完成 KPI，公司仍可能亏损）；② 整体结论不能直接拆成对部分的断言（「用户体验差」推不出「搜索框有问题」）。B.7 的拆解工具正是为处理这对矛盾而设。

B.6 事实、解释、推断、评价、建议：五层区分

同一段材料里的句子身份各不相同，混在一起写，读者就无法区分哪些是可检验的事实、哪些是推测、哪些是立场、哪些是行动要求——这是职场写作最常见的逻辑缺陷，也是模块 04「不要把观点写成事实」的前置训练。

  1. 事实（fact）：可独立验证、真假不依赖立场的陈述。例：「华东区 Q2 投诉量 X 件（数据源：客服工单系统，口径：含重复投诉）。」核心是可核验。
  2. 解释（explanation）：说明事实如何产生。解释是机制性的，检验的是机制链条是否完整。
  3. 推断（inference）：从已知推出未知。强度必须匹配依据并标注依据。
  4. 评价（evaluation）：按某种标准给出的价值判断。必须显式给出标准。
  5. 建议（recommendation）：要求采取的行动。必须落到「谁、做什么、何时前」。

操作方法：逐句编号贴标签，统计各层占比。健康的分析型文档：事实打底、解释居中、推断有限出现、评价附标准、建议收尾；常见病灶是解释缺席、评价冒充事实、建议缺位。层间纪律：下层是上层的弹药，上层不能替代下层。

B.7 拆解复杂问题：问题树、逻辑树与概念图

问题树/议题树（issue tree）把核心问题按「构成」或「路径」逐层拆分。步骤：① 把核心问题写成一句可回答的问句（「华东区投诉量为何上升？」而非「改善投诉」）；② 选择拆解维度：构成拆解（按对象/流程/渠道）或路径拆解（按「为什么/怎么做」）；③ 逐层下拆，每层遵守 MECE；④ 停在「可回答」层：有数据可查、有方法可答、有责任主体；拆到无法回答的粒度仍不停是白费功夫。

逻辑树（logic tree）与议题树近似，侧重因果路径：「问题 → 直接原因 → 更深原因」层层下追到「可干预」的根因层。想覆盖问题各个方面用议题树，想找根本原因用逻辑树。

概念图（concept map）：节点是概念、连线标注关系（导致、属于、支持、矛盾、前提），用于梳理概念网络，尤其能暴露「以为有因果其实只是并列」的连线错误。

共同检查：每层是否同一标准？子问题合起来是否覆盖父问题？叶子是否可回答？为什么树状拆解有效：Sweller（1988, Cognitive Science）的认知负荷理论指出工作记忆一次能处理的信息块有限，层级结构把「同时记住 N 个并列因素」转换为「一次只处理一层」；Mayer（Multimedia Learning, 2nd ed., 2009）的分段与邻近原则也支持分组呈现（教学设计领域的实验证据，迁移到文档结构属理论应用）。

B.8 逻辑链条中的跳跃、矛盾与隐含前提

推理链条出问题有三种形态。

跳跃（gap）：从前提到结论之间有未说明的环节。例：「试点复购提升 20%（前提）→ 应该全国推广（结论）。」缺的环节是「试点代表全国」。发现方法：把前提与结论并排，问「从这句到那句，读者必须额外相信什么？」

矛盾（contradiction）：文档内两个命题不能同真，常以隐蔽形式出现：口径不一致（两处「留存」定义不同）、承诺不一致（结论说「大概率」正文说「必然」）。检测：把关键命题摘成清单逐对比对。

隐含前提（hidden premise）：论证成立必须为真、但从未明说的命题。例：「应该买 A 系统，因为它功能更多。」隐含前提是「功能多 → 更适合我们」——这完全可能为假。错误在于把有争议的前提藏起来。检验：把论证还原成显式三段式，问「哪一步大家未必同意？」

逻辑检查表（分析型文档定稿前执行）：① 每个结论的推理类型？强度是否超过该类型上限？② 关键概念是否有一行操作定义、全文判定一致？③ 每个「导致」是否给了机制，没有的是否降级为「相关」？④ 假设是否显式、约束是否写明、结论是否超出证据范围？⑤ 五层是否分清、跳跃是否补齐、有争议的隐含前提是否公开？

B.9 常见逻辑谬误清单

谬误是推理中反复出现的错误模式；背名词无用，能用它指出「文本哪一句、错在哪、怎么补」才有用：

谬误 定义与识别 示例（示例情境，虚构） 纠正动作
仓促概化 用不足或不具代表性的样本支持一般结论 「三个用户说卡，所以产品体验不行」 说明样本量；结论降级到样本范围
相关即因果 把共变直接表述为导致 「用我们功能的公司增长快，所以功能促进增长」 补机制、列混淆变量、降级为「相关」
虚假两难 把连续光谱压成两个对立选项 「要么现在上线，要么永远失去机会」 恢复中间选项；说明二分依据
诉诸无知 以「未被证伪」当作「已证实」 「没人证明方案不行，所以可行」 举证责任在提出者；列出需验证什么

确认偏误单列：Nickerson（1998, Review of General Psychology）的综述表明它是普遍且稳定的认知倾向。它与其他谬误的区别在于——其他谬误是推理链的局部断裂，确认偏误是证据进入推理链之前的系统偏差：材料库已污染，后面所有逻辑操作都在给污染数据精装修。防御是流程性的：为每个结论显式检索「如果我错了会看到什么」，并认真对待反例。

C. 逐步演示

案例背景（示例情境，虚构）：林蔚是电商公司运营经理，需向总监提交「华东区复购率连续两月下滑」的分析。以下演示完整的逻辑体检与结构重组。

1. 原始材料（问题输入）

林蔚初稿是一份「材料拼盘」，核心段落：

「华东区复购率连续两个月下滑，情况比较严重。我们抽查了三个城市的用户，发现很多人在社交媒体上说我们发货变慢了，看来物流是主要原因。另外竞品最近上了新品，肯定也抢走了一部分用户。我建议立即更换物流商，同时加大补贴把用户拉回来。数据显示，使用我们 App 超过一年的老用户流失最明显，这说明老用户对价格最敏感。总的来说，问题主要在外部，我们内部该做的都做了。」

2. 初始判断

读起来「有数据、有分析、有建议」，但逐句贴标签后问题密集：五层混杂、因果无机制、样本不明、结论超证据。

3. 分析过程

**第一步：五层拆解。**逐句贴标签：「复购率连续两月下滑」是事实但无口径（哪个复购率？数据源？）；「情况比较严重」是评价但无标准；「很多人在社媒说发货慢」是转述事实，「很多」无量化且样本自选择严重；「看来物流是主要原因」是解释但无机制；「肯定抢走一部分用户」是推断但「肯定」超强度；「换物流商+加大补贴」是建议但补贴无成本测算；「老用户对价格最敏感」是解释但无机制无对照；「问题主要在外部」是评价，且与「换物流商」隐含的内部责任混在一起。

第二步：识别推理与跳跃。「社媒抱怨 → 物流是主因」是仓促概化 + 无机制因果；「老用户流失明显 → 老用户价格敏感」是混淆相关与因果；「加大补贴」与「问题在外部」隐含矛盾。隐含前提清单：① 社媒抱怨者代表全体用户；② 发货慢 = 物流商问题。

**第三步：拆解问题树。**核心问题改写为「华东区复购率为何连续两月下滑」，第一层按渠道构成拆解：

复购率为何连续两月下滑？
├─ 新客复购是否下滑？→ 首购体验（履约/商品/价格）哪一环变了？
├─ 老客复购是否下滑？→ 流失的流向（竞品/沉默/品类转移）？
├─ 分母（活跃/购买人数）是否变化？→ 获客减少还是口径调整？
└─ 数据口径是否变化？→ 统计规则两月内是否调整？

**第四步：检查矛盾与缺口。**最下层「口径变化」是初稿完全漏掉的分支——复购率下滑可能是统计口径变更的假象。执行 B.8 检查表：结论强度普遍超标，「导致/说明/看来」均无机制。

4. 结构设计过程

按问题树重组：每个分支一节，节内按五层组织——事实带口径、解释带机制、推断带限定；初稿的「总判断」降级为「待验证的竞争性解释之一」。

5. 修改前/后对照表

# 修改动作 修改前 修改后 解决了什么问题
1 事实补口径 「复购率连续两月下滑」 「近 90 天购买 ≥2 次的用户占比环比下降（数据源：订单库，口径：剔除刷单，待与 BI 确认）」 事实可核验
2 因果降级+补机制 「物流是主要原因」 「假设 H1：履约变慢导致复购下降。机制：发货时长↑→差评率↑→再购意愿↓。检验：对比发货时长高低两组用户的复购差」 相关降级；给出可检验机制
3 建议补约束 「加大补贴拉回用户」 「若 H1、H2（价格敏感）检验成立，优先做 X；补贴为备选，需先过单客成本上限（待财务确认）」 建议有约束有成本
4 补遗漏分支 无 新增「口径变化」排查：统计规则两月内是否调整 补上漏掉的分支；消除「问题在外部」与「换物流商」的隐含矛盾

6. 最终版本（结构节选）

结论（限定后）：复购率下降原因尚未定论；当前证据支持两个竞争性解释——H1 履约体验劣化、H2 价格因素，社媒线索指向 H1 但证据等级低。建议先做三项排查，再决定是否更换物流商。 事实层：复购率环比变化（口径见上）；新客/老客分层复购；发货时长分布变化（均值与长尾分开看）；社媒抱怨主题分布（自选择样本）。 解释层：H1 与 H2 机制链并列，各给可观测后果。 推断层：若 H1 成立且发货时长是主因，「先修复长尾订单、再评估物流商」比「立即更换」更稳妥（依据：切换成本的历史经验）。 建议层：① 本周内完成口径核查；② 分层复购数据；③ 发货时长分层对比；④ 据结果决定是否启动物流商评估。

7. 结果评估

试读反馈：总监能在第一段说出「结论没定，先排查三项」，核心信息传达成功；但他追问「为什么不是直接换物流商」，已在结论段补一句「立即更换的成本与风险见附录」。残留动作：数据口径需与 BI 确认，文中已标注「待核实」。与初稿相比，文档从「表态文」变成「可审查的排查方案」——逻辑体检的价值不是更快下结论，而是让每个结论可被检验。

D. 正例、反例与边界案例

类型 案例 为什么 正确/错误在哪
正确应用 「试点复购提升（观察：三城 X 个月），推测全国推广可能有效（推断），但区域差异未验证，建议先扩一城复核」 归纳结论降级到样本范围，建议与推断匹配 推理类型识别正确，结论强度匹配证据

容易混淆 演绎 vs 归纳：「所有规则要求总监审批（演绎前提）」vs「过去都批了（归纳观察）」 前者必然但依赖制度前提为真，后者概率性且依赖样本代表 推理类型误判导致结论强度误设

E. 实战练习

E.1 基础概念判断

任务说明：判断对错并说明依据。

  1. 「演绎推理能发现新知识，所以科学主要靠演绎推进。」
  2. 「三个试点城市复购都提升了，说明方案在全国有效。」
  3. 「找不到反例，就说明我们的解释是对的。」

输入材料：无，基于 B.1、B.3、B.9 判断。

完成要求：每题给出「对/错 + 推理类型或谬误 + 纠正方式」。

评价标准：引用本模块具体概念作为依据。

参考答案与解析
  1. 错。演绎保真而不增益（B.1）：结论不超出前提，不产生新知识；科学新知主要来自归纳与溯因。
  2. 错。三个试点城市的观察是归纳，只支持「试点范围内可能有效」的概率结论；说「全国有效」是仓促概化。纠正：结论限定到样本范围，并提出扩大验证步骤。
  3. 错。这是诉诸无知（B.9）：「未被证伪」不等于「已证实」；且找不到反例可能是检索方式有问题（确认偏误）。正确做法：列出竞争性解释，为每个设计证伪条件。

E.2 方法应用

任务说明：选一个你工作或学习中的真实问题完成分析准备。

输入材料：你自己的真实问题。

完成要求：① 写出核心问句；② 画一棵问题树（第一层至少 3 个分支，同一标准）并标出两层叶子问题及所需输入；③ 列出一对竞争性解释（H1/H2）及各自证伪条件；④ 用五层标签标注三句话的身份。

评价标准：每层标准一致；叶子问题可回答；证伪条件可观测；五层标注准确。

参考答案与解析

评分维度（开放式）：① 核心问句是否为问句而非议题（「指标为何下降」优于「提升指标」）；② 第一层分支是否同一标准——混用「按渠道」与「按原因」即扣分；③ 叶子问题是否可回答；④ H1/H2 是否真的竞争且证伪条件可观测；⑤ 五层标注的典型错误：把「我觉得」标成事实。若虚构，标注「示例情境，虚构」。

E.3 问题诊断

任务说明：诊断一段推理的问题并修复。

输入材料（示例情境，虚构）：某产品经理的立项陈述——

「上线新客服系统后，投诉量下降了 30%，说明新系统显著改善了用户体验。另外，竞品 A 的投诉量上升了，进一步证明我们的方向正确。建议保持现有投入，不需要调整。」

完成要求：① 指出至少三处推理问题（引用 B.1/B.3/B.9 概念）；② 找出一个隐含前提；③ 重写为结论强度与证据匹配的版本并列出一个证伪性检查。

评价标准：问题定位到具体句子；重写不出现「显著」「证明」等超强度词；证伪检查可操作。

参考答案与解析

问题一：相关即因果（B.3）。「上线后投诉下降 30%」只证明时间先后——同期可能有新品、季节因素、口径变更；「显著改善体验」无机制无对照。 问题二：不相干论证。「竞品投诉上升」与「我们方向正确」无逻辑关系（可能是行业淡季等共同原因），且把中性证据往有利方向解读，属确认偏误式推理。 问题三：结论超范围（B.4）。「不需要调整」从单指标推不出全局。 隐含前提：投诉量下降 = 用户体验改善。可被证伪（用户可能因投诉渠道变麻烦而放弃投诉）。 重写要点：投诉下降 30% 须带口径，并说明变化可能由系统改进、季节因素或渠道迁移造成、尚未区分；证伪检查：对照组投诉量变化、解决率与满意度是否同向下降。

E.4 文本修改

任务说明：把一段「观点冒充事实」的汇报文字改写为五层分明的版本。

输入材料（示例情境，虚构）：

「客户对我们的平台很满意，复购数据也证明了这一点——用过的客户基本都回来了。竞品明显不如我们，他们的功能少、更新慢。所以我们应该乘胜追击，加大投放。」

完成要求：① 给原句逐句贴五层标签；② 重写：事实带口径、评价带标准、推断带依据、建议带约束；③ 写出一条原文本隐含的前提。

评价标准：标签准确；重写版每句话可归入且仅归入一层；隐含前提有争议性。

参考答案与解析

原句标签：「客户很满意」「竞品不如我们」= 评价（无标准）；「复购数据证明了这一点」= 解释冒充事实；「基本都回来了」「功能少、更新慢」= 事实但无口径；「应该加大投放」= 建议（无预算约束）。 隐含前提：复购 = 满意。高度可疑——复购可能由转换成本、合约期限、补贴驱动；若该前提不成立，「满意度」论点整体坍塌，必须显式检验。 重写要点（原文未给数据处应写「待 BI 提取」而非编数）：事实层带口径——「近 90 天购买 ≥1 次的客户中，X% 在下一季度再次购买」；推断层带依据——「复购可能反映满意度，也可能反映转换成本」；评价层带标准——「按 NPS 口径为 X 分（行业基准区间，待核实）」；建议层带约束——「若满意度与复购同向再加大投放，预算上限 Y（待财务确认）」。（示例情境，虚构）

E.5 综合产出

任务说明：对一份真实文档执行完整逻辑体检并输出报告。

输入材料：任选一份你写过的报告或邮件（500 字以上，含分析或建议）。

完成要求：交付四件产物——① 五层标注表；② 推理类型与结论强度审计；③ 逻辑检查表执行结果（标记问题位置）；④ 修订方案（至少五处修改，每处说明依据）。

评价标准：四项产物齐全；问题能定位到原句；修订说明引用具体规则。

参考答案与解析

评分维度（开放式）：① 五层标注是否逐句完成；② 结论强度审计是否区分「必然/概率/假设」三档，常见疏漏是漏掉「显然」「众所周知」这类伪装成事实的句子；③ 检查表是否逐项留痕；④ 每条修改能否说清「依据哪条规则、消除了什么缺陷」——只改文字不解决逻辑问题的不得分。加分项：找出最隐蔽的一处概念偷换。

F. 复盘与知识巩固

核心知识总结

  1. 三种推理各有上限：演绎保真不增益，归纳增益不保真，溯因产出的是假设；结论说过了头，九成是推理类型误判。
  2. 概念靠操作定义落地，分类一次只用一种标准；「导致」二字有门槛：机制 + 排除混淆变量，拿不出机制就降级为「相关」。
  3. 结论强度必须匹配证据强度；假设显式列出，约束写明边界。
  4. 五层区分是分析型文档的骨架：事实带口径、解释带机制、推断带依据、评价带标准、建议带约束；问题树把复杂问题转成工作记忆可承受的层级；检查表是慢思考对快直觉的制度性防御，确认偏误污染证据入口，只能靠主动为反例设计检索来防御。

必须掌握的概念清单

演绎推理；归纳推理；溯因推理；操作定义；MECE；相关关系；因果关系；机制解释；前提；假设；约束条件；隐含前提；逻辑谬误；确认偏误；问题树/议题树；五层区分。

常见错误检查表

  • [ ] 每个结论的推理类型是否明确？强度是否超过该类型上限？
  • [ ] 核心概念是否有一行操作定义？全文口径是否一致（无偷换）？
  • [ ] 每个「导致/说明/证明」是否给了机制或已降级为「相关」？样本是否有数量与代表性说明？假设与约束是否显式、结论是否超出证据范围？
  • [ ] 事实有来源口径、评价有标准、建议到人且有约束？
  • [ ] 跳跃是否补齐、有争议的隐含前提是否公开？是否主动检索反面证据？问题树每层同一标准？

自我评估题

  1. 演绎、归纳、溯因各用一个你工作中的实例说明，并指出各例结论的强度上限。
  2. 「先改版后投诉下降，所以改版有效」缺了什么？写出补全它需要的两种证据。
  3. 五层中哪一层最常被伪装成事实？举一个你最近写过的例子。
  4. 确认偏误为什么比单个逻辑谬误更危险？写出两个针对它的防御动作。
参考答案与解析
  1. 示例（答案合理即可）：演绎——「制度要求总监审批，本单超限，故需总监审批」，上限是必然；归纳——「三城试点复购提升，故方案在相似区域可能有效」，上限是概率（样本内）；溯因——「复购下滑 + 发货时长上升，故假设履约劣化是原因」，上限是待检验的最佳解释。判据：能否说出「该结论在什么条件下为假」。
  2. 缺：① 机制证据（改版哪个环节导致投诉下降）；② 对照/排除（同期其他变化、未改版渠道走势、口径变更）。补法：分层对比 + 对照窗口。
  3. 最常被伪装成事实的是评价（「体验明显更好」「情况严重」——无标准的断言读起来像事实），其次是推断。合格答案应给出实例并改写。
  4. 确认偏误污染证据入口：材料库已被筛选，后续推理再正确也是在为偏差服务（Nickerson 1998）。防御：① 为每个结论显式设计「如果我错了会看到什么」并真的去查；② 列出竞争性解释，给每个分配同等的检验机会。

H. 自测与验收标准

  • [ ] 能对一段文本逐句判定推理类型（演绎/归纳/溯因/非推理），并说明结论强度上限
  • [ ] 能为三个核心概念写出一行操作定义、识别一处概念偷换，并用单一标准做 MECE 分类
  • [ ] 能区分一段陈述是相关还是因果，并指出缺失的机制环节
  • [ ] 能把一段混杂材料拆成五层，且每层有对应处理（口径/机制/依据/标准/约束）
